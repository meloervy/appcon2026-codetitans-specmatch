## What Is SpecMatch?

SpecMatch is a full-stack web application that acts as a **single source of truth** for a company's IT hardware inventory, and uses **AI to objectively match idle devices to employee needs** — before anyone considers buying new equipment.

It answers the question every IT department struggles with:

> *"Do we already own something that fits this person's workload — and can we prove it?"*

The system ensures that existing inventory is always evaluated first, that every recommendation carries visible, per-criterion reasoning, and that procurement is only ever suggested when the fleet genuinely has nothing suitable.

## The Core Loop

```
IT describes a need (role profile or free text)
         │
         ▼
  Gemini 3.1 Flash-Lite extracts structured requirements
  { cpu_tier, ram_gb, storage_gb, gpu_tier, portability }
         │
         ▼
  Matching engine scores every idle device
  Score = (CPU×0.30) + (RAM×0.25) + (Storage×0.15) + (GPU×0.20) + (Portability×0.10)
         │
         ▼
  Ranked results with per-criterion bars & plain-language reason
         │
      ┌──┴──┐
      │     │
   Match  No match above threshold
  found      │
      │      ▼
      │  Suggest procurement (new purchase)
      ▼
  IT assigns the top pick (or overrides)
  Device status → assigned, assignment logged
         │
         ▼
  Mismatch Radar runs continuously
  Flags under-provisioned staff & over-provisioned waste
```

## Feature Overview

### 🖥️ Device Inventory Management
- Register devices with full hardware specs: brand, model, CPU tier, RAM (GB), storage type/GB, GPU tier, device type (laptop/desktop), condition, and lifecycle status.
- Lifecycle stages: `available` → `assigned` → `maintenance` → `retired` → `reclaimed`.
- Maintenance log with cost tracking, technician name, and notes.
- Lifecycle event trail (every status change is recorded with timestamp and actor).
- **Automated Asset Identification (Gemini 3.1 Flash-Lite)**: Type any device model (e.g. "ThinkPad T14 AMD Ryzen 7" or "MacBook Pro 16 M3 Max") to instantly auto-identify CPU architecture, RAM, GPU tier, and storage specifications using AI with structured JSON output and intelligent local heuristic fallback.
- Export device list to PDF.

### 👥 Employee Management
- Register employees with department, position, and profile picture.
- Assign/reassign/unassign devices with full assignment history.
- CSV import for bulk employee onboarding.
- Export employee roster to CSV or PDF.
- Offboarding workflow: unassigns device and archives the employee.

### 🎯 AI Matching Engine (Two-Layer Architecture)

**Layer 1 — AI Requirement Extraction (Gemini)**

Converts free-text workload descriptions into a structured requirement schema:
```json
{
  "min_cpu_tier": "high",
  "min_ram_gb": 32,
  "min_storage_gb": 512,
  "requires_gpu": true,
  "min_gpu_tier": "dedicated-entry",
  "portability_required": false,
  "reasoning": "Adobe Premiere requires hardware-accelerated export..."
}
```

**Layer 2 — Deterministic Weighted Scoring**

Every idle device is scored against extracted requirements:

| Criterion | Weight |
|-----------|--------|
| CPU tier match | 30% |
| RAM adequacy | 25% |
| GPU tier match | 20% |
| Storage adequacy | 15% |
| Portability fit | 10% |

Results are ranked with:
- A **match percentage** (0–100%)
- Individual **sub-score bars** for each criterion
- A **plain-language explanation** of why the device scored as it did

**Role Profiles**: Pre-defined workload templates (e.g. "Software Developer", "Video Editor", "Data Analyst") provide one-click requirement seeding without writing a description.

**Dynamic Inventory Bridge Swap**: A single-hop cascade reallocation — if no idle device fits, the engine finds an overprovisioned active assignment and proposes: swap that person to a smaller idle unit and redirect their current device to the requester.

### 🔍 Mismatch Radar
Continuously scans active assignments and flags:
- **Under-provisioned**: Device doesn't meet the assigned employee's role requirements (performance bottleneck risk).
- **Over-provisioned**: High-spec device assigned to a low-demand role (fleet waste).
- Displays CapEx impact estimates.

### 💬 Fleet AI Assistant (Gemini-powered Chat)
A contextual chat assistant with live fleet awareness:
- Answers questions like "How many devices are available in stockroom?" or "Which employees have mismatched hardware?"
- Backed by a deterministic heuristic fallback when Gemini is unavailable.
- Circuit breaker prevents quota exhaustion.

### 📊 Dashboard
- Summary cards: total devices, available, assigned, in maintenance, retired.
- Assignment distribution chart.
- Recent activity feed.
- Quick-access to mismatch alerts.

## AI Architecture

### Gemini Extraction Pipeline

```
extractRequirements(text)
  │
  ├─ 1. Query cache check (md5 of input) → return cached if hit
  ├─ 2. Demo template check (config-driven exact matches)
  ├─ 3. Offline / circuit-breaker check
  │       GEMINI_DEMO_OFFLINE=true  →  source: offline_heuristic
  │       circuit breaker tripped   →  source: heuristic_fallback
  ├─ 4. SpecMatchExtractionAgent (Laravel AI SDK + Gemini 3.1 Flash-Lite)
  │       429 → set circuit breaker (30 min) → heuristic fallback
  ├─ 5. callGeminiApi() REST fallback (single model, no retry loop)
  │       429/401/403 → set circuit breaker
  └─ 6. Heuristic keyword extraction (always available)
```

### Circuit Breaker Cache Keys

| Key | TTL | Trigger |
|-----|-----|---------|
| `gemini_rate_limited` | 30 min | Any 429 response |
| `gemini_assistant_quota_exceeded` | 30 min (60 min on auth error) | Fleet assistant 429/401/403 |
| `gemini_assistant_service_error` | 5 min | 503 / connection errors |

### Source Field Values

| `source` | Meaning |
|----------|---------|
| `laravel_ai_gemini` | Extracted via Laravel AI SDK + Gemini (live) |
| `gemini_api_direct` | Extracted via direct REST API fallback |
| `offline_heuristic` | `GEMINI_DEMO_OFFLINE=true` in env |
| `heuristic_fallback` | Circuit breaker tripped at runtime |
| `demo_template` | Matched a pre-configured demo template |
| `cache` | Returned from query cache (no API call) |

## Scoring Formula

The weighted match score is computed deterministically:

```
score = (cpu_score  × 0.30)
      + (ram_score  × 0.25)
      + (gpu_score  × 0.20)
      + (disk_score × 0.15)
      + (port_score × 0.10)
```

Each sub-score is a value from 0–100 based on how well the device meets or exceeds the extracted requirement for that criterion. The final percentage displayed in the UI is this weighted sum, and each individual bar reflects its raw sub-score (not the weighted contribution) — making the reasoning fully auditable.

## Gemini Integration Notes

- **Model**: `gemini-3.1-flash-lite` — chosen for free-tier availability, low latency (~3 s P50), and sufficient instruction-following for structured JSON extraction.
- **Circuit breaker**: A 429 response sets a 30-minute cache lock. During this window, the system falls back to heuristic keyword extraction so the app remains fully functional.
- **Offline mode**: Set `GEMINI_DEMO_OFFLINE=true` to disable all Gemini calls (useful for demos without internet or when quota is exhausted).
- **Free tier**: ~20 requests/day on the free tier. For sustained usage, set a paid Gemini API key.
- **Test isolation**: `phpunit.xml` injects `GEMINI_DEMO_OFFLINE=true` and `GEMINI_API_KEY=""` so tests never consume quota.

## TechSpecs API Notes

- **Base URL**: `https://api.techspecs.io/v5`
- **Auth**: `x-api-id` and `x-api-key` headers.
- **`/products/search`**: Minimum `size=10` required by the API.
- **`/products/{id}`**: Returns full nested spec JSON; `TechSpecsService::mapToDeviceAttributes()` normalizes it to the SpecMatch device schema.
- The TechSpecs integration is entirely optional — devices can be registered manually without it.
